# 部署者可以不配置对话模型，改用纯自带密钥模式

ADR-0006 假设部署者承担默认模型的费用：没有自带密钥的用户用部署者的模型，限额防止滥用。这个决定增加另一种部署方式：**`CHAT_LLM_BASE_URL`、`CHAT_LLM_API_KEY`、`CHAT_LLM_MODEL` 三项全部留空时，服务器不保存任何默认对话模型**，每个文字回合和通话都必须由用户在客户端「自带密钥」里填写 LLM（ADR-0017），服务器只在该回合处理期间持有它。

## 决定

- 三项 `CHAT_LLM_*` 全部留空 = 纯自带密钥（BYOK-only）模式；填齐 = 原来的部署者模式。只填一部分拒绝启动。
- `BACKGROUND_LLM_*` 不能单独配置；没有对话模型时后台模型也必须留空。
- 纯自带密钥模式下跳过对话模型的启动检查；部署者仍可配置向量化、重排、判断模型、语音合成/识别和生图，这些继续由部署者承担。
- 文字回合没带 `own_keys.llm` 且部署者没有对话模型时，在记录活动和扣限额之前拒绝：HTTP 429，`retry_at: null`，消息「这个部署只能用自带密钥，请在设置里填写 LLM」。客户端据此引导到自带密钥设置。
- 通话同理：缺 LLM 拒绝；缺语音合成或识别且部署者也没有时，503 提示自带语音密钥。
- 起标题用回合携带的用户后台模型（`memory_llm`，没有则用其 LLM）。记忆提取仍需要部署者的向量化、重排和判断模型；没配置就关闭，文字对话不受影响。
- 搭话（GLOSSARY.md「搭话」）用部署者的对话模型，纯自带密钥模式下没有部署者模型。ADR-0030 之后，用户可以把自己的搭话模型加密保存在服务器上；没有部署者模型时，只有保存了搭话模型的用户会被搭话。
- 管理后台不能在没有 `.env` 对话模型时新增对话/后台模型；要改回部署者模式，先在 `.env` 里填齐并重启。

## Considered Options

- **新增一个环境变量开关**：多一个需要解释和测试的状态；三项留空本身就足以表达「没有默认模型」，而且部分配置会被拒绝，不会误判。
- **强制所有部署都自带密钥**：会破坏现有的部署者模式、公开部署和 ADR-0006 的默认体验，范围过大。
- **把向量化/判断模型也做成客户端可配**：需要改自带密钥的接口、校验和费用模型，留待以后。

## Consequences

- 纯自带密钥部署没有默认模型费用，但用户不填 key 就无法对话；记忆、剧情回忆、好感度、照片在没有部署者服务 key 时关闭。
- 拒绝发生在活动记录和限额之前，不消耗用户额度；客户端已有的 429 + `retry_at: null` 处理直接复用。
- 管理后台中对话/后台模型显示为不可用，不能再通过后台把默认模型加回来。
- `.env.example` 的 `CHAT_LLM_BASE_URL` 改为空，复制后默认进入纯自带密钥模式；要部署者模式就填齐三项。
- 旧的 `EIDOLON_OWN_LLM_REQUIRED` 仍然无效；本决定不恢复它。
