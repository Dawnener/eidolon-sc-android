# 搭话模型可以由用户提供，服务器加密保存

ADR-0017 让用户的 API key 只留在浏览器里，随每个回合和通话发给服务器，用完即弃。搭话
（ADR-0026）却在用户不在线时由服务器生成，那时浏览器不在，服务器手里没有用户的 key。
ADR-0028 的纯自带密钥模式因此把搭话整个关掉了。

用户希望搭话用他们自己的模型，而不是部署者的。这个决定允许用户把一个**只用于搭话**的模型
交给服务器保存，同时保持文字回合和通话的自带密钥约定不变。

## 决定

- 新增 `reach_out_models` 表，每个用户至多一条，存一个加密的 `LLMSettings`（地址、key、模型、
  接口类型、思考强度、额外参数）。
- 加密用 `EIDOLON_SECRET_KEY` 经 HKDF 派生的 Fernet，和后台覆盖、封禁哈希的派生分开（不同的
  info）。没有 `EIDOLON_SECRET_KEY` 时拒绝保存并明确说明；服务器可以解密。
- API：`GET/PUT/DELETE /api/account/reach-out-llm`。PUT 先用和自带 LLM 相同的检查（流式 +
  工具调用）试一次，通过后才加密保存；GET 只返回地址、模型、接口类型和 key 末 4 位，永不返回 key。
- 搭话优先用该用户保存的模型；没有才用部署者的对话模型；都没有时这个用户不会被搭话。
- 搭话用用户自己的模型时，运行记录标为 `own_keys`，费用不归部署者，也不计入用户限额。
- 文字回合和通话仍然只使用浏览器随请求带来的 key；纯自带密钥模式不变。
- 删除用户时这条记录一起删除。

## Considered Options

- **把 key 只留在手机，App 在后台醒来时触发搭话**：服务器完全不保存 key，但手机离线、关机或
  Android 限制后台任务时就没有搭话；覆盖不了「用户不在线时她先说话」的主要场景。
- **继续要求部署者配置一个对话模型**：能用，但会和纯自带密钥模式冲突，且费用由部署者承担。
- **把用户 key 放在 `.env` 或明文数据库**：不适合多用户，也会让 key 出现在日志或备份里；
  Fernet 加密至少把密钥和数据库文件分开。

## Consequences

- 用户可以在 App 里填自己的搭话模型，即使部署是纯自带密钥模式也能收到搭话。
- 这个 key 在服务器上，服务器（以及拿到 `EIDOLON_SECRET_KEY` 和数据库的人）可以解密；这是让
  搭话在用户离线时仍能发生所必须付出的代价，和 ADR-0017 的「只留在浏览器」不同。
- `EIDOLON_SECRET_KEY` 必须设置，且不要更换，否则已保存的搭话模型无法解密（会当作没有）。
- 用户换模型时 key 不会回显，必须重新填写。
- ADR-0028 中「纯自带密钥模式强制关闭搭话」的结论由这个决定取代：搭话开关可以打开，没有部署者
  模型时只对设置了自己搭话模型的用户生效。
